# Pieces, Effects, Programs and the Compose Lab: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace bree's hand-written text effects with effects composed from pieces (moves and modulators) on blits arcs, play programs of them, and build a compose lab for designing effects and programs.

**Architecture:** A *piece* is a move (draws the message on `lit`) or a modulator (drives one channel by a curve, spread by an order). An *effect* is JSON-able data placing pieces in `enter`/`active`/`exit`; one staging function turns it into blits `ArcSpec`s for a message on a board. A *program* is a program owner holding one owner per step, placed end to end, each holding its step's arcs. The compose lab is a second Vite page built on the same staging function.

**Tech Stack:** TypeScript 7, `@msb235/blits` (local `../blits` checkout at `2a98ed7` or later, for `mix.arc`), Vite 8, Vitest 4, biome, Playwright for the lab smoke.

**Spec:** `docs/superpowers/specs/2026-10-22-compose-design.md`

## Global Constraints

- `mix.arc` is unreleased: until blits publishes, typecheck and build resolve `@msb235/blits` from `../blits/src` (Task 1 points `tsconfig.build.json` at it); the `package.json` pin stays `0.11.0` until a release, as `TODO.md` says.
- Published source (`src/`) uses relative imports with `.js` extensions; `lab/` and `test/` import bree through `@/`.
- Effects, pieces, orders and programs are plain JSON-able data (no functions), so they round-trip through a URL hash and `JSON.stringify`.
- Dot size is fixed (Mike, 2026-10-22); `glow` changes halo strength only.
- No hand-written text-effect patch survives beside its piece version: `src/effects/` and `src/show.ts` are deleted by the end of Task 7.
- Tests run one file locally with `node_modules/.bin/vitest run <file>`; the whole suite, typecheck, build and smoke run on the fleet (`onto test`; `onto do --kind typecheck|build|test …`). Never run the whole suite, `tsc` or `npm run check` on the controller.
- Files stay under a few hundred lines: one move family or modulator family per module.
- US English; columns of numbers in the lab use `font-variant-numeric: tabular-nums`; the lab root never scrolls (`scrollTo(0, 5000)` leaves `scrollY` 0).

## Review Focus

- **Empty message** (`text: ''` or spaces only): every move stages without throwing and the step still lasts its hold, showing nothing. → test in Task 3.
- **Message wider than the board on a centered move:** it clips, never throws, and `stageEffect` returns a warning naming the move. → test in Task 6.
- **An effect with every slot empty, or hold 0:** stages to a step of length 0 that the program skips past without stalling the loop. → test in Task 7.
- **A shared link naming a move, modulator or effect that no longer exists:** the lab loads the rest and lists what it dropped, not a blank page. → test in Task 10.
- **Two pieces in one slot both setting `tint`:** stages, plays, and warns. → test in Task 6.

### Task 2: Settings and orders

Settings (`params`) gain choice and color-list kinds; orders give each subject a rank, a delay and a group.

**Files:**
- Create: `src/params.ts` (moved from `src/effects/effect.ts`'s `Param`/`Params`/`Values`/`values`, extended), `src/orders.ts`, `src/hash.ts` (moved from `src/effects/hash.ts`)
- Modify: `src/effects/*.ts` imports only, so they keep compiling until Task 7
- Test: `test/params.test.ts`, `test/orders.test.ts`

**Interfaces:**
- Produces:
  - `type Param = NumberParam | ChoiceParam | ColorsParam`
    - `NumberParam { label; min; max; step; value: number; unit? }`
    - `ChoiceParam { label; choices: readonly string[]; value: string }`
    - `ColorsParam { label; colors: readonly number[] }` (its value is `readonly number[]`)
  - `type ParamValue = number | string | readonly number[]`; `Values<P>` maps each key to its kind's value; `values(of: { params: P }, given?: Partial<Values<P>>): Values<P>`
  - `type OrderBy = 'together' | 'column' | 'column-reverse' | 'center' | 'row' | 'letter' | 'random'`
  - `interface Order { readonly by: OrderBy; readonly lag?: number; readonly seed?: number }` (lag default 0, seed default 1)
  - `interface Placed { readonly board: Board; readonly text: Bitmap; readonly left: number }` and `place(board: Board, text: Bitmap): Placed` (left = `leftOf`)
  - `rankOf(order: Order, at: Placed): (s: Subject) => number`: integer ≥ 0. Dots: by their column, reversed column, distance in columns from the board's center, row, letter index (`floor((x - left) / ADVANCE)`, clamped to the message), or a seeded permutation of columns. Cells rank by `i` for every order except `together`.
  - `delayOf(order, at): (s: Subject) => number` = rank × lag
  - `spanOf(order, at): number` = largest delay over the board's dots
  - `groupsOf(order, at): readonly (readonly Led[])[]`: the board's dots grouped by rank, ascending rank, empty groups dropped

### Task 6: Effects

**Files:**
- Create: `src/effects.ts` (the new effect module; the old `src/effects/` directory is deleted in Task 7)
- Test: `test/stage.test.ts`

**Interfaces:**
- Consumes: `stagePiece`, `groupsOf`, `spanOf` (Task 2), blits `ArcSpec`
- Produces:
  - `interface EffectSpec { readonly name: string; readonly about?: string; readonly enter?: SlotPieces; readonly active?: SlotPieces; readonly exit?: SlotPieces; readonly hold?: number; readonly blend?: number; readonly order?: Order }`. `order` is the whole-effect order of the spec's "an order can apply to the whole effect".
  - `stageEffect(effect: EffectSpec, at: Placed, hex: number, hold?: number): StagedEffect`
  - `interface StagedEffect { readonly arcs: readonly { readonly spec: ArcSpec<Subject, Pose>; readonly start: number }[]; readonly ms: number; readonly warnings: readonly string[] }`
    - With no whole-effect order: one arc on all dots (and cells where a modulator plays on them), start 0.
    - With one: an arc per group from `groupsOf(order)`, start = rank × lag, subjects = that group's dots. Modulators that play on cells go in the first group's arc only.
    - `ms` = latest start + that arc's enter + hold + exit lengths.
    - `hold` argument overrides the effect's; with neither, an active move's own length (scroll-across's crossing), else 0.
  - `cueEffect(m: Mix<Subject, Pose>, owner: Handle<Subject>, staged: StagedEffect, name: string): void`: cues each arc with `owner` and its `start`.
  - The step color is one voice per arc writing `tint` at weight 1 over the arc's whole length, so layered move pieces never carry it twice. A modulator writing `tint` plays at weight 3 by default, so it outweighs the step color rather than averaging with it evenly.
  - Warnings: every piece's, plus `two pieces in <slot> set tint` when a slot has more than one piece writing `tint`.
